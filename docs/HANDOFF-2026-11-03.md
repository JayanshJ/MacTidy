## What MacTidy is

A native SwiftUI macOS app (SwiftPM, no Xcode project) that reclaims disk space and audits
startup items. macOS 14+. It builds with the Command Line Tools alone. It is not sandboxed and
is ad-hoc signed. Repo: https://github.com/JayanshJ/MacTidy

- **CoreKit:** library with all scanner and safety logic. No UI, fully unit-tested.
- **MacTidyApp:** SwiftUI executable that depends on CoreKit. `AppState` is the UI's only gateway
  to destructive actions.

## Rules you must not break

- Every destructive action follows one path:
  `ScanItem → DeletionPlan → SafePathPolicy.classify → Trasher.trash`. Items only ever move to the
  Trash. `CloneDeduplicator` is the one other mutator.
- Never call `removeItem`, never run `rm`, and never bypass `SafePathPolicy`.
- New destructive features must record to `TrashLog` and `CleanupLog` through `AppState`.
- Never add the App Sandbox entitlement. It breaks scanning, trashing and cloning.
- **No byte may be counted twice.** The Overview total sums every category, so a new source or
  category must not overlap an existing one. Each byte has one owner.
- Only `Risk.safe` items are ever preselected. Caution and Danger items are listed but need
  explicit selection. Scheduled runs use the same gate.
- Scanners are read-only. Do not test by moving or renaming real files on this Mac. See
  "Past incidents".
- Keep logic in CoreKit with tests. Do not put scanner or safety logic in views.
- Do not touch the owner's real files, empty the Trash, or run a real cleanup. Those are the
  owner's to do.

## Commands

```sh
make test   # always this, never plain `swift test`, which can silently run 0 tests
make app    # release build to dist/MacTidy.app, then codesign
make run    # app + open
make clean
```

Tests use Swift Testing (`import Testing`, `@Suite`, `@Test`, `#expect`), not XCTest.

Design check, using fixture data with no scanning or trashing:

```sh
make app && dist/MacTidy.app/Contents/MacOS/MacTidy --snapshot <dir> --only overview,cleanup
```

It renders screens in light and dark to PNG and logs `LAYOUT OVERFLOW` if a screen's minimum
height exceeds the window. UI rules are in `Theme.swift` and `AGENTS.md`: one accent colour, and
never a card inside a card.

`MACTIDY_REAL_HOME=1 make test` prints detection results for this Mac.

## Release and install procedures

Do these only when the owner asks. Pushing directly to `main` is this repo's convention.

**Release**

1. Bump the version and build in `Support/Info.plist` with `sed`. `PlistBuddy` reorders the keys.
2. Run `make test`.
3. Commit by naming the files. Do not use `git add -A`, because `.claude/` is untracked.
4. Push to `main`.
5. Run `make release NOTES=path/to/notes.md`.
6. Verify: download the published zip, extract with `ditto -x -k`, run `codesign -v`, and check the version.

The in-app updater reads the GitHub `releases/latest` tag and the `MacTidy.app.zip` asset, so the
asset name must stay the same.

**Install locally**

1. `make app`
2. Quit the app: `osascript -e 'tell application id "com.jayansh.mactidy" to quit'`
3. Move `/Applications/MacTidy.app` to the Trash through Finder.
4. `ditto dist/MacTidy.app /Applications/MacTidy.app`
5. Check with `codesign -v` and `cmp`, then `open` it.

Ad-hoc builds are pinned by cdhash, so Full Disk Access must be granted again after each new build.
`make cert` creates a self-signed certificate that fixes this for good.

## Past incidents

- **Credentials listed as Safe (fixed in v1.17.0).** `~/.sbt`, `~/.fastlane` and `~/.pub-cache` were
  listed whole as Safe in v1.16.0 and earlier, and they can hold credentials. The sources are now
  narrowed (`.sbt/boot`, `.fastlane/caches`, `.pub-cache/hosted`, `.pub-cache/git`), and the secrets
  were added to `SafePathPolicy.credentialPaths`. Lesson: before adding a whole-folder source, check
  what else lives in that folder.
- **An agent went past a read-only brief.** It tried `rename` probes on real folders under
  `~/Library/Containers`. Nothing moved. The owner was told. App Containers stay detected but not
  offered, because moving one is refused without Full Disk Access and is unverified with it.
- **Two owners for one byte.** Telegram was claimed by both `AppSupportRules` and `HandledElsewhere`,
  and a test caught it. `HandledElsewhere` owns it now.

## The owner's question that led to this

"How to get the most storage and RAM safely cleared." The answer given:

- **Storage:** choose what to remove by how much it costs to lose it, and remember that space only
  returns once the Trash is emptied.
- **RAM:** no safe "clear" button helps. macOS already uses free RAM as cache, and cleaners only evict
  it, which makes things slower. What really frees memory is quitting the apps holding it and reducing
  what starts in the background.

## Proposed work (none of it approved)

**Recommended order:** RAM items 1–3 and storage item 2 first, since they are small and fix wrong or
missing results. The "Free up X GB" plan comes next as the main new feature.

### RAM

1. **Fix the idle-app list (confirmed bug).** `MemoryCard.swift:101` does
   `ProcessScanner.scan().filter(\.isSafeToQuit).prefix(5)`, which takes the first five *processes*.
   "Quit 5 idle apps" can therefore mean five helpers of one app, with wrong byte counts and duplicate
   names. `isSafeToQuit` (`ProcessScanner.swift:29`) means a bundle path, not on the denylist, and CPU
   under 1%, so an app in active use can qualify. `idleSeconds` is always 0 because frontmost tracking
   isn't wired up. Fix: roll up per app, exclude the app in use, and track when each was last frontmost.
2. **Show real per-app memory.** Use `phys_footprint` from `proc_pid_rusage` rather than summed RSS.
3. **Only prompt when it matters.** Suggest quitting apps only when memory pressure or swap is real.
4. **Detect leaks.** If an app's memory keeps growing over hours, suggest restarting it.
5. **Show the memory cost of login and background items** in Login Items.
6. **Remove "Purge disk cache".** `MemoryCard.swift:56-61`, backed by
   `MemoryMaintenance.purgeDiskCache`. It only drops file cache that macOS evicts under pressure anyway,
   and it needs an admin prompt. Recommended, but removing a feature is the owner's call.

### Storage

1. **"Free up X GB" plan.** The user states a target, and MacTidy picks the lowest-cost set: Safe first,
   then re-downloadable, then items that need a reinstall, showing the cost of each. Caution items need
   explicit approval. It must go through the existing pipeline.
2. **Find build output through git.** Use read-only `git --no-optional-locks check-ignore` to find
   ignored build output, and also accept Swift `.build` folders beside an xcodeproj. The marker check is
   at `DevRootsScanner.swift:27` and `CategoryScanner.swift:137`. List these as Caution, ranked by
   coldness. Adds about 7.8 GB here. Check for overlap with `bigFiles` and the existing build categories.
3. **Scan more folders for big files.** `bigFiles` only checks Downloads and the dev roots. Adding
   Documents, Desktop and Movies as review-only items helps non-developers most.
4. **Empty Trash from the app.** **Needs the owner's decision first.** `TrashNudgeCard.swift:5-8` and
   the card's text state that MacTidy never empties the Trash, as an explicit invariant. The proposal is
   a user-triggered button through Finder with a confirmation, never scheduled. Do not build this without
   a clear yes. `TrashLog` and the Undo flow would also need to handle items that are gone for good.
5. **Spot things that grow back.** Warn when a cleaned item returns within days, and flag active
   projects' build folders. `ScanHistory.growthReport` and `CleanupLog` are the starting points.
6. **Report what was really freed.** Compare free space before and after emptying. Clones and hard links
   make sizes over-promise; for example, Claude Code 2.1.312 is hard-linked.
7. **Account for the whole disk.** Break down apps, home, Library, system, snapshots and purgeable space,
   and label normal items such as `sleepimage`. This would explain the 28 GB gap above.
